# Split Screen

You and what you're talking about, on screen at once: the screen is split 50/50 — visuals on top, the client (their talking-head video) below.

**From Basic:** text hook Yes/No and its 4 styles, 4 caption styles, 4 fonts, brand color, Fast/Chill pacing — the client chooses them like in Basic.
**Set by this format (locked):** the hook sits on the split line for the first ~3 seconds, then the captions appear in the same spot (no hook → captions from the start); the camera is always static (no zoom).
**Own elements:** the 50/50 layout (the engine crops the client's video into the bottom half; a **horizontal** recording is reframed automatically during `ccc build` — a virtual camera follows the speaker's face with one fixed zoom, the head centered with room above it for captions; the build prints `▶ Reframe … lice u N/M uzoraka`, and if no face is found it uses a calm centered shot — mention that to the client); the **top half** — Dark or Light style (`top_style`), filled with "moments" you plan from the transcript (below).

## Top half — real assets first (research, before the visual plan)

**Hierarchy — for every moment take the FIRST level that has good material:**
0. the client's own file (dashboard / chat) → 1. a link the client gave → 2. **a real asset from the internet** (logo, news headline, website/app screenshot, product photo, short video clip) → 3. native platform recreation (Instagram DM/comment…) → 4. real numbers as stat/chart → 5. custom animated template (flow, versus, steps…) → 6. kinetic headline.
Real assets always beat custom animations when the speaker talks about something concrete that exists (an event, a person in the public eye, a character, news, a study, a post or article). A **tool, app or brand named in a sentence** is shown by its whole logo inside a custom animation that dramatizes the sentence (`principles.md` 1–4) — a screenshot of its homepage is not "the real thing", it gives no context. Custom animations fill everything else.

**Before planning, read `../principles.md`** — the shared CCC principles from every review (meaning first, frameworks, logos, layout, CTA). They win over anything below where they differ.

**The client's choice (dashboard → `choices.json`):** `web` (true = "Find real visuals online", the default; false = "Animated visuals only") and `links` (pages the client says they mention). `ccc research <name>` prints both.
- **Links first (level 1), always — even with `web: false`.** For each link: open it (WebFetch), find the word ids where the client talks about it, and download the right asset from that exact URL (`ccc shot <link> --find "<headline>"`, an X/Twitter status link → the embed URL with the same id, `ccc fetch` for an image link, `ccc clip` for a video). A link that matches nothing in the transcript: don't force it — say so in one sentence in the summary.
- **`web: false`** → no searching and no other downloads (the engine refuses them and the check fails): only the client's links, their files and the animated templates (levels 0, 1, 3–6).
- **`web: true`** → the full research step below.

**Research step** (after the editorial pass, only with `web: true`):
1. Read the kept transcript and name the video's **subject** — the one concrete thing the whole video is about (an event, a campaign, a product launch, a person's story), if there is one — then every concrete entity: brands/companies, products/apps, websites, people (also people the speaker only names, like a marketing lead), characters (a TV role like "Kevin from The Office"), news/events (with date), studies/numbers. Decide the ideal asset for each (footage / photo / logo / headline / screenshot / post). Give each a `match` list of phrases — the engine finds EVERY mention by itself, so you don't miss later ones. Write `work/<name>/research.json`:
   `{"subject": {"name": "Ramp's glass-box stunt with Kevin from The Office", "type": "event", "match": ["glass box", "stunt"], "want": "footage", "status": "found", "assets": ["web-clip-ramp-glass-box.mp4"]}, "entities": [{"name": "Ramp", "type": "brand", "match": ["Ramp"], "want": "logo", "status": "found", "assets": ["web-logo-ramp.png"]}, {"name": "Kevin Malone (The Office)", "type": "character", "match": ["Kevin"], "want": "photo", "status": "found", "assets": ["web-photo-kevin-malone.jpg"]}]}`
   Status: `found` / `not found` (searched, nothing usable) / `asked client` / `client file`. People, characters and events are never `skipped` — the engine flags it.
2. Find sources with WebSearch / WebFetch, then download with the engine (every file gets its source recorded — never save web files any other way):
   - **Logo:** `ccc logo <name> "<Brand>" --domain brand.com` → look at the candidates sheet (Read the path) → `ccc fetch <name> <url> --for <wID> --as logo-<brand>`. Prefer the official, current, full-color logo (Wikimedia's "… logo 2022.svg" style or the site's own); never a random site. The sheet can contain look-alikes — pick the logo of exactly that brand (Meta ≠ Meta AI, Notion ≠ Notion Press), the current one (X, not the Twitter bird; candidates marked ⚠ are old/parody/"prohibited" versions), compare with the brand's own site when unsure. "nema nijednog kandidata" → a flow node with an icon + the name, or a screenshot of their site.
   - **News / article / website / app page:** `ccc shot <name> <url> --for <wID> --find "<exact headline or phrase on the page>"` (add `--mobile` for a phone layout). It closes cookie banners, removes every fixed overlay (consent boxes, "heads up" popups, sticky headers, chat buttons) and ad slots/banners, and finds the phrase; use a distinctive phrase (the headline, or one sentence of a paragraph), not a single word. Add `--mark "<exact text on the page>"` (repeatable) for every name or figure the speaker says while the page is on screen (e.g. `--mark "Rohan Kumar" --mark "$250,000"`) — the engine records their exact position so they can be highlighted on the word. A shot that is mostly empty (ad space, white page) is refused; `⚠ … veći od ekrana` means the found part is cut — use a shorter phrase. Prefer the publisher's/brand's own page. The engine refuses walls — `Nije sačuvano: …` for a bot/captcha check, 404, paywall, login wall or HTTP error (preview in `_candidates/`); only if you looked at the preview and it's actually fine, repeat with `--keep`. Known from the stress test: NYT, WSJ, G2 and Instagram profiles are walled for automated visits; BBC, Guardian, Spiegel, Le Monde, Wikipedia, Reddit, LinkedIn company pages and X profiles work. For a walled news site: the same story from another outlet, or a `news` card with the real headline (find it with WebSearch), the outlet's logo and date. `nije nađen` for `--find` → the shot is kept without a focus; `--crop` with a missing element fails (post deleted/private).
   - **Photo / image:** `ccc fetch <name> <image-url> --for <wID>` — official/press images or Wikimedia Commons; no watermarked stock (Getty, Shutterstock), no private people. Photos of people: only public figures in their public role (CEO, creator, politician), a current, flattering, sharp portrait.
   - **A real post the speaker quotes or refers to** (a tweet, a Reddit thread, a LinkedIn post): find the actual post. X/Twitter: `ccc shot <name> "https://platform.twitter.com/embed/Tweet.html?id=<id>&theme=dark" --selector article --crop --for <wID>` — gives just the post card on a transparent background. Other sites: `ccc shot … --selector "<post element>" --crop` if the page allows it; otherwise recreate it natively with a `post` card using the post's exact text, author and numbers.
   - **A number from a study/report:** find the original source; put the number in a `stat`/`chart` and the source in `"source"` (never shown on screen — it goes to the report). If the speaker's number differs from the source, use the speaker's words and mention it in the report.
   - **Video clip:** `ccc clip <name> <url> --for <wID> --from <s> --to <s>` (≤ 20 s, the part that matters; YouTube, news sites, reels work).
   - **A brand's real ads** (any video about ads, marketing, offers): the Meta Ad Library — `ccc shot <name> "https://www.facebook.com/ads/library/?active_status=active&ad_type=all&country=US&q=<brand>&search_type=keyword_unordered" --find "<exact ad text>" --mark "<the offer the speaker says>"`. It is real proof of what the brand runs right now ("This ad has multiple versions", "free shipping with any $40+ order"). The engine sometimes calls it a wall (403) — look at the preview; if the ads are there, repeat with `--keep`.
   - **Product images:** the brand's own store (Shopify stores serve them from `cdn.shopify.com/s/files/…`): find the product image URL and `ccc fetch` it — a single product on a plain background is the ideal actor for a `scene` (clone/cycle).
   - **What a person DOES** ("Selena is making content, telling her founder story, showing before and after"): real clips from official channels — the brand's YouTube (get-ready-with-me, tutorials, campaign films) and reputable interviews (TIME, Vogue…). 4–8 s each, `ccc clip … --from --to`; look at frames every 0.5 s and pick a `start` without burned-in text or b-roll of something else.
   - **The main people of the video get 3–4 DIFFERENT portraits** (Wikimedia Commons: search the person, open the File pages, `ccc fetch` the originals) so they can be present through the whole video (principle 42) without one picture repeating — a picture appears at most twice (faces on `faceoff`/`pillars` count). Reject portraits with strangers' hands, a tiny face, blur, or a crop through the head.
   - Research is independent of template work — run it in a background agent with this list as its brief while you plan, then check every file it reports yourself.
   - **The subject's footage comes first** (the real event, ad, stunt or launch): search YouTube, news sites, X, the brand's own site and press pages, not only where it went viral. If it exists only on Instagram/TikTok and `ccc clip` can't get it, **ask the client** in one sentence — *"Do you have the clip of <subject>? Drop it here and I'll use it — real footage works much better than an animation."* — set the subject's status to `asked client`, continue with everything else, and when the file arrives: `ccc assets <name> --add "<path>" --note "<subject>"` → status `client file`. Real footage always beats a custom animation.
3. **Look at every downloaded file** (Read it) before using it: correct entity, current (date fits), sharp enough, no watermark, no popup/ad over it, readable on a phone. For a video clip, look at its frames every ~0.5 s and pick a `start` where the part you show is clean — clips from other creators often have their own text burned in, and some seconds show only sky or buildings. If it fails, try the next source, then go one level down the hierarchy.
   - **Check the speaker's facts against the sources** while researching (place, date, names, numbers). Never "correct" the speaker on screen — use their words — but note every mismatch in the summary (e.g. *"The stunt was at Flatiron Plaza, not Times Square"*), so the client can decide.
   - **Claims about named people or companies** (revenue, scandals, "they lost", "fake"): on screen only what a reliable source confirms, shown as that source (screenshot with the figure marked). Unconfirmed or disputed → no graphic at all; the speaker's words carry it and the summary mentions it. Never a red/`bad` tone on an unconfirmed fact.
   - **A vague reference** ("like this guy", "that one ad") that the sources can't pin down: don't guess a person or a thing — keep the current visual on screen (the subject, or the last person) and mention it in the summary.
4. Budget per video: about 15 searches, 25 downloads, 4 minutes. Hero opening and the main claims first.
5. `ccc research <name>` shows the entity list and everything downloaded with sources.
6. Never show source labels on screen. The final report lists every real visual with its source automatically (from the recorded sources and `source` fields) — read it out to the client in the summary.

**Real-asset kinds:**
- `logo` — `file` (+ `name`, `sub`) for one brand in the neon tile; or `logos: [{file, name, at}]` (2–4) — big tiles that are all there from the start, dimmed, and each lights up with its name on the word that names it (e.g. "at WME and Patreon"). A `flow` node can also show a real logo: `{"file": "web-logo-x.png", "label": "X", "at": …}`. Logos on a white background get it removed automatically.
- `screenshot` — `file` from `ccc shot`; the engine already knows where the `--find` phrase is, so just add `"highlight": {"at": "<wID>"}` — the camera glides to that part from the first frame and the rest dims with it. `"marks": [{"text": "MrBeast", "at": "<wID>"}]` — names/figures recorded with `--mark` get a brand-color marker on the word they're said and the camera eases a little closer so the phrase sits in the middle. Marks only on the main (highlighted/found) part — never on a small tag or a dimmed area (the engine refuses those). In the first ~10 s, when the point is not to give the answer away, use `"blur": true` on the mark: that phrase is blurred from the first frame for as long as the screenshot is on screen (never shown, then hidden; no zoom). The camera always makes ONE straight move from the first frame to the final framing (the highlighted part, or the marker inside it), never a second turn; the highlighted part ends in the middle of the top half and is never cut — a wide headline makes the view wider so it fits. Never type coordinates by hand (`x/y/w/h` are refused — guessed boxes cut through text); if the part you need wasn't found, shoot again with a better `--find`. Optional `device: "phone"`.
- `news` — `headline` (exact), `outlet`, `date`, `logo` (outlet logo file), optional `image` (article image file; a face in it is kept in frame), `highlight: [{"text": "words from the headline", "at": wID}]` — highlighted when said. Long headlines need reading time (~3.5 words/s; the engine warns `ima N reči … treba ~Xs`): give the moment that time, or keep the real headline's main clause and end it with "…".
- `photo` — a real person / product / place: `file`, `name` (e.g. "Adam Mosseri"), `sub` (role, e.g. "Head of Instagram"), optional `at` for the name tag. When the whole head fits, it fills the top half with a slow zoom for the whole scene and a name tag pointing up at the person; when the head would be cut, the person goes into a white card with the name tag under it — automatic.
- `spotlight` — **a hook when the footage alone doesn't say what's happening**: the subject's footage/photo big (a vertical clip fills the top half edge to edge with a blurred copy behind it), optionally a short punchy `title` (`{text, at}`, ≤ 26 characters) in a brand-color box over it and the company's `logo` (`{file, at}`) popping in at the side on its word. `fx: {"type": "vanish", "at": wID}` — on that word the picture glitches and fades to a grey ghost (a reveal like "she doesn't exist", principle 21). When the footage clearly shows the event, open on the footage alone (`video`/`image`, full screen) — the text hook is already there; no extra title or logo. Hooks must be clear and striking, never look like a scene from the middle of the video.
- `faceoff` — **two sides compared, both in frame from the first frame** (principle 31): `sides: [{file, name, logo: {file}, values: [{text, at, tone, label}]}]` × exactly 2 — a photo card per side (face centered), the brand logo pinned to the card, the name under it, and values that land on their word and replace each other on the same card (`label` = what the number is, e.g. "revenue, last 30 days"; `tone: "good"` = brand-color glow, `"bad"` = red and slightly muted). A VS badge sits between them. Use it whenever the video (or a stretch of it) is "X vs Y": the hook of a comparison video, two founders, two products, two prices. Keep one faceoff to 3–5 s of the same look (principle 37): follow the same two people, but switch presentation — faceoff → `pillars` for their numbers → faceoff with the next claim.
- `pillars` — **numbers of 2–3 compared subjects, each bar topped with that subject's face** (principle 38): `bars: [{file, name}]` (face photo; or `logo: {file}`), `sets: [{label, at, values: [n…], display: ["$4.2M", …], tones: ["good", "bad"], note: {text, at, tone}}]`. The first set grows the bars from zero on its word; every next set morphs the same bars to new heights (followers → revenue: "more reach, but 6x less revenue"), the faces ride on top. `display` is what is written (the speaker's words); `values` only set the heights. `note` = the takeaway pill ("6x less revenue"). Never a lone `stat` for a gap between two named subjects.
- `scene` — **full-screen custom animation that recreates the process the speaker describes** (principle 36): the whole top half is the stage and REAL assets act it out on their words. `actors: [{id, file | icon | text, x, y, size, aspect, at}]` (x/y = centre in top-half pixels 1080 × 960, safe zone y 240–840; `size` = width; `aspect` = height/width, default from the picture) + `beats: [{at, do, target, …}]`:
  - `move` {x, y, scale} · `dim` · `focus` (everyone else is muted) · `swap` {file} (new picture in the same frame) · `exit`
  - `clone` {n, cols, x, y, scale, gap} — the actor multiplies into n copies laid out in a grid ("10 versions of the same ad")
  - `cycle` {x, y, rx, ry, speed, scale, icon} — the copies start circling an ellipse around a spinning recycle badge ("recycled over and over") — needs a `clone` first
  - `tag` {text, x, y, tone} — a label pill lands; `stamp` {text, tone} — a tilted stamp ("SAME AD")
  Use it whenever the viewer has to IMAGINE something happening to concrete things (multiplying, recycling, piling up, being replaced, growing, falling apart) — that is the default for such sentences; template cards are the fallback. Example ("Kylie runs the same ad with 10 different versions, recycled over and over, just pushing the product"): actor = Kylie's real lip ad; `stamp` "same ad" on "same ad"; `clone` n 10 on "10"; `cycle` on "recycled"; `tag` "Just pushing the product" (bad) on "over and over".
- `mediatext` — the real thing on one side, what's said about it on the other: `file` (image or video clip; `start` for a clip), `lines: [{text, at, tone}]` (1–4 short lines, each on its word; earlier lines dim), optional `title` (small label, e.g. the brand), `side` (`left` default = media left), `more: [{file, at}]` — 1–2 more pictures that replace the first one inside the same shape on their words (scenes longer than ~5 s, principle 20). The shape is upright (430×560): a face is centered automatically; a wide picture, collage or two-shot is refused — show it full-width instead (principle 18). Use it when the speaker explains something about the subject/person while it should stay visible (e.g. "Ramp's in-house team, led by …").
- `posts` — 2–3 real posts about the subject stacked on top of each other, each arriving on its word: `items: [{file, at}]` (screenshots from `ccc shot … --crop`) or native post data (`platform`, `text`, `name`, …, `at`) — only real posts with their real text.
- `post` — a social post: `platform` (`x` | `reddit` | `linkedin` | `threads`), `text` (exact), `name`, `handle`, `avatar` (file), `time`, `verified`, `likes`/`comments`/`reposts`/`views`, Reddit `community` + `title`, LinkedIn `headline`; `highlight: [{"text": "exact words from the post", "at": wID}]` — marked as the speaker reads them (read-along). Or `file` = a real post screenshot from `ccc shot … --crop` (shown as a floating native card). **Never invent a post and attribute it to a real person or brand** — a native `post` only recreates a real post the speaker quotes, with its real text; for a hypothetical example use a generic name ("a founder", handle like `@yourclient`), never a real account.
- `image` / `video` work for downloaded web files too. A vertical clip/photo (phone format) automatically fills the top half edge to edge with a blurred copy of itself behind it; `caption` shows on it.
- Numbers in `mediatext` lines, `stat` values and photo name tags count up when they appear (ranges too, when both numbers are ≥ 10).
- `stat` / `chart` with numbers from a source: add `"source": "Hootsuite Digital Report 2026"` (report only, never on screen).

**How pictures are shown (automatic — know it when planning):** an image or screenshot fills the WHOLE top half (no window) whenever the highlighted part can sit in the middle of the safe zone without touching an edge or being cut; a picture with a one-color edge (phone screenshots, white websites) blends into a top-half background of that color so any part can be zoomed; only otherwise it gets a browser/phone window. The camera always zooms in a straight, smooth line to the highlighted part, and the highlight is a flat cut-out: that part stays full, the rest fades into the background color. So choose `--find` phrases that are the exact thing being talked about — that's where the camera goes. Camera timing fits the scene: the camera moves from the very first frame (never still, then a sudden jump), glides into the highlighted part and arrives just after the word that names it, and the background dims together with the zoom (same curve, same length); the last part of the scene is still so people can read it. Give every screenshot moment at least 1.8 s and let the highlighted word come at least 1.2 s before the moment ends (the engine warns otherwise). Pictures without a highlight (and full-bleed photos) get a slow zoom for the whole scene. Real logos always sit in the same dark neon tile as icons.

## Top half — the story map (before the visual plan)

Every video gets its OWN structure, built from its own story. Same CCC style, never the same sequence of visuals as another video (the engine compares with earlier videos on this computer and warns). Before writing the plan:
1. **Subject and roles.** Split the kept transcript into its story parts: hook, context, the story/event, people involved, numbers, reveal or lesson, call to action. Note which sentences mention the subject or an entity from research.json.
2. **Treatment per sentence**, in this order of preference:
   - it mentions the **subject** → its real footage/photo, and come back to it each time it's mentioned (continue the same clip rather than cutting to something else);
   - it mentions a **person, character, company, product, post or article** → that real thing (photo with name tag, logo tile, screenshot with the spoken words highlighted, the real post);
   - it's a **number** → if it's a claim about the subject (followers, price, views, cost): its **proof** — the source as a screenshot with that figure marked (principles 16–17); only a general number with nothing to show gets a stat/chart, merged with the sentence that introduces it (label first, value on the word);
   - it's a **comparison of two named subjects** (people, brands, products) → both stay in frame together: `faceoff` for who/what, `pillars` with their faces for their numbers — and keep following them through the comparison, switching presentation every 3–5 s (principles 31, 37, 38);
   - it **describes something happening to concrete things** that the viewer has to imagine (one ad copied 10×, recycled, prices dropping, followers pouring in, a product selling out) → `scene`: recreate that process full-screen with the real assets as actors (principle 36). This is the default for such sentences — not a flow/checklist card;
   - it describes **what a person does** (makes content, tells a story, shows before/after) → real clips of that person doing it (principle 42);
   - only a truly **abstract idea** (a feeling, a principle, a contrast with nothing concrete to show) → an animated template, chosen for what the idea IS (sequence → flow, contrast → versus, selection → filter, list → checklist…), never because the last video had one there. Templates are the last resort (principle 36);
   - the **CTA offer** → `resource` with its real contents as `rows` (the video's own framework delivered), visible from the first word of the CTA (principle 43).
3. **Rhythm and variety.** Alternate real footage/photos, cards and text. Never two similar-LOOKING moments in a row, even with different templates (list → list, number card → number card — principle 41). Something new at most every 5 s (principle 37). The same template at most twice per video and never twice in a row; when you use `flow` twice, give it different `layout`s. `mediatext` at most 4 times and never twice in a row — alternate its `side`. The same picture on screen at most twice (a deliberate callback, like going back to the person when their fee is mentioned). Not every sentence needs a new visual — a strong clip can carry two or three sentences.
   - **A number that belongs to something concrete** stays next to it: the stunt's cost next to the stunt footage (`mediatext`), a person's fee in their name tag (`photo` with `name: "$30K–$70K"`, `sub: "his fee per speaking gig"`). A bare `stat` card only for numbers that stand on their own.
4. **Continuity.** Scenes connect: the same footage continues across sentences (one longer moment, not two), a headline never announces text the next visual shows again (merge them), and a list/flow that builds on the previous scene keeps its look.
5. Write each moment's `"why"`: one sentence on why this visual fits this sentence (the engine requires it). If the why is "to have something here", pick something better.

## Top half — the visual plan (your job, after the story map, before `ccc build`)

**Editing psychology — follow it strictly (these come from CCC's own reviews):**
1. **Hero opening = the first claim, decided with `principles.md` 30–35.** Ask in order: who/what is the video about → show that, recognizably, from frame 0; is it a comparison → `faceoff` (both sides in frame together, numbers land on their side); the opening runs until the first claim is complete (often ~10 s) and continues while the next lines are about the same comparison — as 2–3 consecutive moments with the same subjects, the look changing every 3–5 s (timing table in `principles.md`). When the subject has real footage, open on that footage, full screen; if the footage alone doesn't say what's happening, use `spotlight` (short title + logo). Never a plain `headline`/`key`/`stat`/lone logo when the real subject exists. Calm is fine — the subject carries the attention, not speed.
2. **Timing: follow the one table in `principles.md`** (a look 3–5 s, a new beat at least every ~3 s, a real clip up to 8 s, the hook as 2–3 moments of one idea). About one moment per phrase. Nothing stands dead still: pictures zoom slowly, cards and tiles enter with movement, numbers count up (automatic).
3. **Show, don't repeat.** The visual explains or dramatizes what's said (process, comparison, filter, growth, time, checklist, chat) — never just the caption again. `headline` only for abstract punch lines.
4. **Every graphic must be readable without sound.** No bar, line or number without its meaning: give scales (`of`), axis labels (`y`, `x`), and the takeaway (`note`). If you can't explain a number visually, don't draw a bar.
5. **Sync every part to its word** with `"at": "<word id>"` — including secondary labels (`sub`, `note`, chart values). Nothing appears before it's said; the first part appears immediately.
6. **No lone fragments.** Never let a single filler word ("Your", "The", "So") stand alone — the first chunk on screen must carry meaning by itself (e.g. "Your lead magnet", not "Your" … "lead magnet"). If the meaningful word comes later, start the moment later.
7. **Never reveal what's coming.** Steps: one `steps` moment per step; the card shows the full shape with the text hidden until it's said. Lists/checklists/chats only show items that were said.
8. **Enter at the start of the phrase that introduces it** — `at` = the first word of that phrase ("**has** to work", "**your** ICP"), never its last word. Late entries force rushed animation.
9. **Time to process.** Every element must stay long enough to be read and for its animation to finish (the engine prints `'…' je na ekranu Xs, a treba bar Ys` — a `[must]` line; fix it: enter earlier, or end the moment later).
10. **No redundant beats.** If the next visual carries the same idea ("views" → a Views-vs card), don't show it as text first — start that visual on that word.
11. **Color psychology.** Bad / risk / loss → `"tone": "bad"` (red); everything else → the brand color (no third color — `warn` is drawn in the brand color, principle 27). Use it on headline highlights, checklist items (bad = red ✗), notifications, stat subs and chart notes (a declining chart is red automatically).
12. **Native to the platform.** When a visual recreates a real app (DMs, comments), use `"platform": "instagram"` so the design and colors say Instagram without any logo (not the brand glass style).
13. **Light sweep is an accent, not a default.** The engine puts it on the opening and on a few payoff moments, at least 12 s apart, only on the main card. To force it on a special moment add `"sweep": true` to that item (still spaced); `"sweep": false` turns it off.
14. **Focus control** happens automatically: in lists, flows and chats the earlier items dim when a new one arrives — so plan lists in the order they're spoken.
15. Use the client's exact words and numbers; never invent facts or numbers.
16. **Concrete → real.** Whenever the speaker names something real (the subject, a person, a character, a company, a post), show the real thing; an icon or a headline instead of it is a mistake (the engine flags it when research.json has an asset for it).
17. **No template structure.** Never reuse the order of visuals from another video or from an example; the engine warns on repeats inside the video (`zaredom`, `monoton`, same flow layout) and on similarity to earlier videos. Fix the `[must]` lines; `[aim]` lines get at most 2 revisions (SKILL.md Step 4).

The templates already handle the rest automatically: every visual is sized to fill the safe zone, groups re-center smoothly as parts are added, lists grow downward in reading order, lone headline text gets a highlight that draws under the accent word, and the background stays subtle.

**Kinds** (short texts — labels ≤ 22 characters, headline words ≤ 14):
- `flow` — a process / cause → effect: 2–4 `nodes` `{icon, label, at}` (or `{file, label, at}` for a real logo), line draws to each node as it's said. `layout`: `row` (default), `column` (top to bottom, labels on the right), `quad` (3–4 nodes: down → right → up), `hub` (3–4 nodes: node 0 — usually a tool's logo `{file}` with no label — on top, every other node below, a line from the hub to each: "X does A, B, C") — vary it when flow appears more than once. (No diagonal layouts.) With `quad` only: `loop: {at}` closes the last node back to the first and the dots keep circling (a cycle / self-improving loop), `center: {text, at}` writes the loop's name in the middle — reuse the previous flow's nodes so the loop visibly closes the same system.
- `search` — a recreated search bar for "using X like a search engine" type claims: `logo: {file}` (whole logo inside the bar), `query: {text, at}` (typed), optional `placeholder`, optional `meter: {value, label, used, at, tone, usedLabel, wasteLabel}` (a power/usage bar: `used`% lit, the rest red and striped, `value` counts up on its word).
- `versus` — old way vs new way / wrong vs right: `left {label, sub}` gets crossed out, `right {label, sub, at}` glows with ✓.
- `steps` — the video's **framework** (`principles.md` 6–7): 2–5 `items`, `active` = current step (0-based), one moment per step and EVERY step gets one. `active: -1` = the announcement ("I set up four files"): N tiles (`icon`, default folder) with "?" — names hidden — plus optional `total: {text, at}` (tiles slide down, a bracket joins them, the shared value appears above). `active: N` = all delivered (names revealed one by one with ✓) — e.g. the CTA resource "a template with all four files", with `title`.
- `checklist` — qualities / requirements: `title`, `items` `{text, at, tone}` appear and tick one by one (`tone: "bad"` = red ✗).
- `filter` — selecting the right people from many: `label`, `at` (when the filter happens), `keep` (1–6), `sub`, `total` (12–28).
- `chart` — growth or decline: `bars` (2–7 numbers, the shape only unless the client said the numbers), `label` (what is measured), `y` (axis, e.g. "Engagement"), `x` (one short label per bar, e.g. ["Post 1", …]), `note` (`{text, at}` — the takeaway, e.g. "Audience burned out"), optional `value`.
- `stat` — a number the client says: `value` (counts up), `label`, `sub` (`{text, at}`), and only if there is a real scale: `of` (e.g. "of 168 h in a week") + `ring` (0–100 = the share).
- `week` — time per week/day: `value` ("3–4 hrs"), `label`, `per` ("≈30 min a day"), `days` (default 7), `sub` (`{text, at}`) — 7 day columns fill one by one, the total counts up.
- `chat` — DMs: `title` (the other person's username), `messages` `{from: "them"|"you", text, at}`, `platform: "instagram"` for a native Instagram DM look.
- `notify` — things piling up (calls, leads, followers, sales): `items` `{icon, title, body, at, tone}` (max 4), top to bottom.
- `resource` — the offered resource (report, guide, template) as an object for the CTA: `title` (`at` = its word), `sub` (`{text, at}`), `badge` (e.g. "FREE REPORT", `badgeAt` or `{text, at}`), `icon`, `rows` — the resource's REAL contents as 3–5 text lines (`["Static ads that actually sell", {"text": "…", "at": wID}]`; the first lines are visible from the first word of the CTA, later ones may land on their word — principle 43; a number instead of a list draws placeholder lines, only when there is truly nothing to show), `kicker` ("REPORT"). Build the rows from what the video delivers (its framework, its steps) unless the client gave the real document. Use it right before the `comment` moment (principle 28).
- `comment` — one comment + reply: `text`, `user`, `reply`, `author`, `at` (when the reply appears), `platform: "instagram"` for the native look. **CTA "comment KEYWORD"**: `text` = the keyword, `platform: "instagram"`, `typing: true` — typed into "Add a comment…", posted big, heart, reply on `at`.
- `headline` — abstract punch line: `words` = meaningful chunks `{text, at}` (never a lone filler word), `accent` = the chunk that gets the drawn highlight, optional `sub` (`{text, at}`).
- `key` — fallback only: `icon`, `line1`, `line2`.
- `image` / `video` — the client's own file (see Client files below): `file`, optional `start` (video), optional `caption` (`{text, at}`, only if it adds information).

**Client files (optional).** The client can drop screenshots, screen recordings or clips on the dashboard (with an optional note per file); they're listed in `choices.json → assets`. Before planning:

- **Look at every preview** (Read the preview path — an image, or 4 frames with times for a video) so you know what is in each file.
- Place each file on the sentence it belongs to: the client's note first, then what the file shows, then the file name. A file replaces the auto visual for that moment (`kind: "image"` / `"video"`, `file` = the exact name from the list, optional `start` = second in the clip to start from). Everything without a file keeps auto visuals.
- An image stays ≥ 1.5 s; a video moment may be as long as the part of the clip you want (a long screen recording can cover a long stretch — it moves on its own). Short clips freeze on their last frame.
- Use every file once if it fits anywhere; if a file fits nowhere (or can't be used — the list shows `✗` with the reason), don't force it: tell the client in one sentence which file wasn't used and why.
- `caption` on a file only if it adds information the speech doesn't (e.g. a label on a screenshot) — never repeat the spoken words.
- `⚠ niska rezolucija` in the list: the file will show small (never stretched more than 2×). Use it only if it still makes sense small; otherwise tell the client it's too small and ask for a bigger version.
- Transparent PNGs (logos, cut-out objects) are shown without a frame, floating with a shadow — good for brand logos and product shots.
- Files sent later in chat: `ccc assets <name> --add "<path>" --note "<when>"`, then re-plan and build.

Then `ccc build <name>`. The check line `gornja polovina: …` must pass (whole video covered, every moment ≥ 1.2 s, every `at` inside its moment, files exist).
